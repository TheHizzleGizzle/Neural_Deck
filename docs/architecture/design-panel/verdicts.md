## Designer summaries

### minimal: Minimal interface

Design written to docs/architecture/design-panel/design-minimal.md

SHAPE: Deck has two entry points. `send(Action)` is the one way in; `attach(Screen)` is the one way out, delivering an immutable `State` through `Screen.render`. `State` carries flat rows, graveyard views, profiles, the loading-bar text and one-shot `Cue`s. Deck is process-scoped, not ViewModel-scoped. Behind it sit IdeaTree (`of`, `rows`, `kin`), IdeaEngine (`run`), ProviderProfile (`problem`, `chatUrl`) and DeckFiles (`load`, `save`). There are three ports: `ModelText`, `ProfileStore` and `Deck.Screen`.

DISTINGUISHING IDEA: the UI learns exactly one module. Activity, sheets and `IdeaCardAdapter` only send Actions and render State; Prompt Lab and ping also go through Deck. No model object, file, preference or network call crosses the seam. Flight guard, session-id targeting, saving, publishing and lifecycle queueing are therefore written once and inherited by every gesture. Filter, splice selection and active skill live in Deck.

BIGGEST WEAKNESS: the vocabulary did not shrink. Two entry points carry 22 Action kinds and 8 Cue kinds behind a loosely typed dispatch. There is also no cancel and no queue, so a hung request blocks spark, branch and splice deck-wide for up to 65 seconds. Two new user-visible strings need a decision.

Full design: [design-minimal.md](design-minimal.md)

### flexible: Maximum flexibility

Design written to docs/architecture/design-panel/design-flexible.md (about 2,100 words of prose plus code; nothing in the app repository was touched).

SHAPE: Deck has three methods: dispatch(action), state(), subscribe(listener). MainActivity and every sheet send Actions.x(...) values and render one immutable DeckState: rows, lens, splice selection, active skill, provider settings, request lanes, the derived loading-bar entry, and ack-able one-shot notices. Deck lives in a ViewModel and is confined to the UI thread. Each request binds its session id, anchor cards, prompt facts and provider profile at dispatch.

DISTINGUISHING IDEA: the set of kinds is open, the set of effects is closed. Request kinds (Move), tree views (Lens), prompt facts (ContextSource) and model-text sources (TextSource chain) are values handed in. A reply can only add cards at a Landing, annotate existing cards, or hand text back. Undo, a taste profile, converge/score, streaming and new filters each arrive as a new value, with no interface change.

BIGGEST WEAKNESS: breadth and weak static checking. It has roughly 30 public types and a 28-factory action vocabulary for a 3,300-line app. Facts keys, Ask options and Result's three nullable slots are unchecked conventions, and several seams are open for futures that may never come.

Full design: [design-flexible.md](design-flexible.md)

### common-caller: 7.5 / 10

**Strengths.** The only design that checked the manifest: with no usesCleartextTraffic and targetSdk 36, local http is blocked by platform default today; it adds the manifest attribute (not under res/) and makes EndpointRule the single gate. Most conservative on saved data: no datum moves. `active_session_id` stays a pref that is still written, KeyVault is reused as the Secrets adapter, the KeyValues port has float accessors for the `temperature` pref (storage/AiConfig.java:50; a string-only port would throw ClassCastException), and commit writes one provider. One Deck per process with the lost-update reason stated; attach in onStart, and `detach(this)` in onStop is a no-op unless that screen is attached, so two instances cannot detach each other. Effects queue and only reach an attached screen. Sheets pull deck.state() and call verbs; they register nothing with the Deck, so rotation cannot leave a zombie listener. The FIFO ticket queue keeps what the single worker thread does today (no tap is dropped) and makes the bar truthful with no new string. Every state-dependent string sits in one pure class under golden tests; the ones I checked against the source match (splice bar, collapse label, tags line, session line, banish codes, short and long Prompt Lab toasts). Stamps updatedAt on the session that changed (MainActivity.java:568 stamps the active one). The complexity test counts passes instead of timing. Cut-over is the Activity first, then sheets one at a time.

**Weaknesses.** DeckState has no seed field, so a new Activity over the live Deck cannot fill the dock. A queued spark records 'intent only', so two queued sparks with different text both use the later text. The step-5 claim that old sheet signatures survive on one-line shims fails for GraveyardSheet, which mutates session.graveyard in place and reports through an argument-less callback. LabReply and PingReply have no cancel and fire into a sheet that rotation already destroyed. 'Verticals extend across the row's bottom margin' names no mechanism. Two new strings are added as fact. IdeaCard.depth is removed at step 2 while the client, repository and Activity still use it. 'Do not call a verb from inside render' is unenforced. Depth is unclamped. The offline Prompt Lab fallback now hops threads, so the busy label flashes where today it never appears. It moves more strings than any other design (mitigated by the golden tests). HttpModelSourceTest uses com.sun.net.httpserver, which only exists on a desktop JDK. Details and fixes are in flaws_in_winner.

### minimal: 6.5 / 10

**Strengths.** Gets the lifetime right: one Deck per process (DeckApp), with the reason stated: a ViewModel dies with a finished Activity and a relaunch would open a second Deck over the same file. Attaches in onStart and detaches in onStop, and cues queue while detached, so no dialog can open on a stopped or destroyed Activity. Re-entrancy is defined (a send made inside render runs afterwards). Sheets are rendered through the Activity's `sheet` field, so the Deck never holds a dead sheet. One of two designs that noticed the 10dp row margin in item_idea_card.xml and bridges it with an ItemDecoration without touching res/. The most careful store: rename over the live file, .bak taken once per launch, corrupt file quarantined. It flags the two new strings (quarantine, cleartext refusal) as decisions instead of adding them. ProfileStore.commit writes one provider, as today's SAVE does. State carries the seed, so a fresh Activity can fill the dock.

**Weaknesses.** onStop calls `deck.attach(null)`, which detaches whatever is attached; if a second MainActivity instance starts, its onStart runs before the first one's onStop and the new screen is detached. A second request while one is in flight is silently ignored, whereas today it queues on the single worker thread (ai/OpenAiCompatibleClient.java:35), so taps that used to work now do nothing and no string says why. The SEED cue fires whenever the saved seed changes, so an ordinary spark rewrites the dock and resets the caret (MainActivity.java:246-253 never touches the dock), and the Prompt Lab load loses today's setSelection (line 370). The active-session pointer moves out of the `active_session_id` pref into the sessions file; the pref is read but no longer written. Step 7 moves MainActivity, GraveyardSheet, SkillsSheet and the adapter in one change, after step 6 lands a complete but unwired Deck. Nothing about the manifest: cleartext to localhost is blocked by platform default, so 'cleartext allowed when local' cannot work as designed. Depth is unclamped (18dp per level, PixelBranchConnectorView.java:47), which narrows cards on deep trees. The complexity test uses @Test(timeout), which is wall-clock and spawns a thread.

### ports-adapters: 5.5 / 10

**Strengths.** Lowest string risk: toast literals stay where they are in the Activity and sheets (Outcome return values select them), only the three loading messages and three failure codes move into Deck under JVM test, and no new string is added. The only design that cleans up on destroy: onDestroy detaches and dismisses the open sheet, the sheet's dismiss listener detaches its own listener and cancels its Pending, and the engine never calls back after cancel. The offline Prompt Lab fallback runs inline before submit returns, matching today's no-flicker path (ui/PromptLabSheet.java:77-82). True depth lives in the data while the view keeps a pixel budget, so deep rows are no narrower than today. The dock is set only when the session id changes, and because attach is in onCreate the framework's later restore keeps typed text across rotation. AiConfig becomes the prefs adapter in place, a small diff. Storage health is in the snapshot. It lists its behaviour changes as decisions to confirm.

**Weaknesses.** The Deck lives in an AndroidViewModel and onCleared only shuts the worker down, with the comment that an in-flight reply 'still finishes, applies and saves'. After back-press and relaunch (the Activity finishes on API 26-30) that orphan Deck and the new one both write neural_deck_sessions_v1.json from different in-memory states, which is the lost update the two process-scoped designs call out. The final step moves MainActivity, all four sheets and the adapter in one commit and says it cannot be split: the largest big-bang here, after a step that lands an unused Deck. Attaching in onCreate and detaching in onDestroy means it renders and opens the failure dialog while stopped, and an effect shown on a finishing Activity is acknowledged and lost. ProviderSettingsStore.save writes the whole vault (same key-wipe exposure as flexible: storage/KeyVault.java:31-33, 73-75). ByokDraft.typed substitutes defaults for a blank URL or model on PING, where today a blank URL reports 'Missing Base URL...' (ui/ByokSettingsSheet.java:101-110, ai/OpenAiCompatibleClient.java:290-292). The active pointer moves into the sessions file. A second request returns BUSY and is dropped (today it queues). The 10dp row margin is never mentioned, so rails still stop short between rows. No manifest change for cleartext. No thread assertion. HttpModelTextTest uses com.sun.net.httpserver, and byte-exact golden store files are brittle because the JVM org.json artifact and Android's differ in key order and number formatting.

### flexible: 4.5 / 10

**Strengths.** Best migration slicing of the four: sheets become callback-only before Deck exists (step 6), Deck lands first without requests while the old client's replies go through a temporary session-id-bound action (step 7), then requests (step 8). Deck throws on any thread but its own. Subscribes in onStart and closes in onStop. Notices need an ack, so a failure is not lost when no screen is there. Bridges the 10dp row margin with an ItemDecoration. ProviderSettings matches storage: temperature and global context are global (storage/AiConfig.java:49-63), profiles are per provider. Revive keeps today's index-0 placement. Lanes keep today's ability to start several requests. Prompt Lab toast literals stay in the sheet.

**Weaknesses.** Carries the most new machinery onto a codebase with zero tests: about 30 public types, an undo journal that serialises the session to JSON before every transaction on the UI thread, streaming partials, marks/meta, and open Move/Lens/ContextSource plug points, none of which has a button today. The Deck lives in a ViewModel and onCleared calls close(), which cancels running requests; back-press finishes the Activity on API 26-30, so the reply is dropped, against constraint 7. Sheets subscribe themselves and unsubscribe in setOnDismissListener; on rotation the BottomSheetDialog is torn down as a leaked window without onDismiss, so the ViewModel-scoped Deck keeps calling a dead sheet and pins the destroyed Activity. A finished Prompt Lab result stays in `requests` until dismissed, so reopening the lab renders a stale result and toast at once. ProviderStore.save writes the whole settings value: KeyVault.getApiKey returns "" on any decrypt failure (storage/KeyVault.java:73-75) and saveApiKey("") removes the slot (31-33), so one bad read followed by SAVE can wipe every provider's key, where today only the selected one is written. Adds a second state file (neural_deck_state_v1.json) for the active pointer. `busy` shows the latest-started label and swaps back when it finishes. No manifest change for cleartext. The BYOK usage snippet passes a Draft where using(ProviderProfile) is declared.

### Ideas to graft onto the winner

- From minimal, section 3 'UI' (also flexible, section 3 'Rails'): draw the pass-through verticals in the gap between rows with a RecyclerView.ItemDecoration that reads the same Rail values. The row root in item_idea_card.xml carries layout_marginBottom=10dp and the connector is a child of that row, so it cannot paint into the margin. This replaces the winner's unspecified 'verticals extend across the row's bottom margin'.
- From minimal, section 1.1 invariants ('The dock text stays a view'): put the saved seed in the snapshot and have a freshly created Activity copy it into the dock once. Do it in onCreate only when savedInstanceState is null, so rotation keeps the typed text the framework restores.
- From minimal, section 1.1 invariants ('Thread'): a verb called from inside render is queued and runs after that render returns. This replaces the winner's unenforced 'do not call a verb from inside render'.
- From minimal, section 3 'DeckFiles': write temp, fsync, then rename over the live file (one atomic step, the live file never disappears), and keep .bak as the last good file from the previous launch. The winner's 'current to .bak, then rename' leaves a moment with no live file and makes .bak only one tap old.
- From minimal, section 5 ('Two new strings need a decision'): treat the quarantine toast and the cleartext refusal as questions for the owner, with 'no new string' as the default, instead of adding them as fact.
- From flexible, section 7 migration steps 6 to 8: first make the sheets callback-only with ids (no sheet mutates a session or touches a store); then land Deck for everything except requests, with the old client's replies applied through a temporary session-id-bound verb (this closes defect 1 early); then move requests. This splits the winner's one large step 5 and makes its shim claim true.
- From flexible, section 1.4 'ProviderSettings': keep temperature and global context as vault-wide values separate from the per-provider profile (they are single prefs, storage/AiConfig.java:49-63). Keep the winner's single-provider commit; do not adopt flexible's whole-settings save.
- From ports-adapters, section 2 Usage (MainActivity.onDestroy) and section 1.2 'probes': the Activity dismisses any open sheet in onDestroy, optimise and ping return a Pending with cancel(), and each sheet cancels in setOnDismissListener. The engine never calls back after cancel. This replaces LabReply and PingReply firing into a destroyed sheet.
- From ports-adapters, section 1.4 ('The fallback is the engine's decision'): when the profile is not usable, run the offline heuristic inline and call back before the call returns, so the Prompt Lab button never flashes REWRITING_VIA_NEURAL_LINK... where today it does not (ui/PromptLabSheet.java:77-82).
- From ports-adapters, section 1.3 (last paragraph): keep true depth in Rail but give PixelBranchConnectorView a pixel budget that draws only the innermost columns, so rows deeper than 4 are no narrower than today.
- From ports-adapters, section 1.1 'SessionsStore.Health' and DeckState.storage: expose OK / RESTORED_BACKUP / QUARANTINED / SAVE_FAILED in the snapshot, so a storage problem is observable and testable even if no new string is approved.
- From flexible, section 3 'Banish / revive' (and ports-adapters, section 5 'Behaviour decisions to confirm'): revive the whole subtree as a root at index 0, as today, or list 'under the old parent' as a decision with its list position stated.

### Flaws remaining in the winner, with fixes

- DeckState has no seed field. MainActivity.java:156-158 fills the dock from the session on every onCreate; with a process-scoped Deck, an Activity recreated after back-press (process still alive) gets an empty dock because no setDock effect is queued. Fix: add DeckState.seed and fill the dock in onCreate when savedInstanceState is null; keep setDock for open, create, delete and loadSeed, and have it call setSelection(length) as line 370 does today.
- A queued spark loses its own text. Tickets record 'intent only' and the request is built from the session seed when the ticket reaches the head, so two queued sparks typed with different text both use the later text; today the seed string is captured at the tap (MainActivity.java:258). Fix: the ticket carries what the user typed or picked at the tap (seed text, skill); only tree-derived context (lineage, sibling titles, active rules) and the provider profile are read at start.
- The step-5 claim that sheets keep their old signatures on one-line shims does not hold for GraveyardSheet. It takes a BrainstormSession, mutates session.graveyard in place and reports toggle and purge through an argument-less onGraveyardUpdated() (ui/GraveyardSheet.java:107-134); once Deck hides the session, a shim cannot know which entry changed. SkillsSheet likewise writes through BrainstormRepository itself (ui/SkillsSheet.java:98-108, 211-214). Fix: add a step before C1a that makes both sheets report ids through their listeners (onToggleRule(id), onPurge(id), onRevive(id), onForge(...), onDeleteSkill(id)), then do the Activity cut-over.
- LabReply and PingReply have no cancel and outlive their sheet. After rotation the Deck still holds the callback and fires into dead views for up to the 65 s timeout. No crash, but it pins the destroyed Activity and a result can be consumed by a sheet nobody sees. Fix: return a cancellable handle, cancel on dismiss, and dismiss open sheets in onDestroy.
- The rail fix names no mechanism for crossing the 10dp row margin, and depth is unclamped. PixelBranchConnectorView is a child of the row whose root carries the margin, and onMeasure indents 18dp per level (ui/PixelBranchConnectorView.java:47), so depth 15 takes 276dp of a roughly 360dp phone. Fix: ItemDecoration for the gap; a column budget in the view while Rail keeps the true depth.
- Two new strings are added as fact (quarantine toast, cleartext refusal), against constraint 3 as written. Separately, ready() is defined as endpoint().problem(key) == null; if problem() includes the cleartext refusal, a saved 'http://remote + key' config flips the badge to SET_KEY and shows 'Configure your BYOK API key first.', which is the wrong message. Fix: get sign-off on both strings; keep ready() equal to today's rule (URL present, key present unless local) and surface a cleartext refusal at request time through the existing *_FAILED alert.
- Every verb saves, and the new save is JSON plus fsync plus two renames on the UI thread; today's write has no fsync (storage/BrainstormRepository.java:209-214). On slow flash a star or collapse tap can stall. Not measured. Fix: serialise on the UI thread and hand the string to one background writer that keeps only the latest pending snapshot, flushing on detach; tests inject a direct executor. If measurement shows no stall, keep it synchronous but use the single rename-over scheme.
- IdeaCard.depth is removed at step 2, but it still has users then: ai/OpenAiCompatibleClient.java:129 and 173 (parent.depth + 1), MainActivity.java:431, the eight-argument constructor used throughout storage/BrainstormRepository.java:127-186, and the codec in model/IdeaCard.java:50 and 72. Fix: at step 2 stop reading it for rendering and write the JSON key from the tree; delete the field in the last step, as the other three designs do.
- 'Do not call a verb from inside render' is a rule with no enforcement; a violation re-enters validate, mutate, save and render mid-render. Fix: queue re-entrant verbs until the current render returns, or throw IllegalStateException.
- ProviderProfile carries temperature and globalContext per profile, but they are single prefs (storage/AiConfig.java:49-63). On a chip tap `draft[0] = deck.profile(id); fill.run()` can overwrite unsaved temperature and context edits; today a chip tap refreshes only URL, model and key (ui/ByokSettingsSheet.java:50-63). Fix: model them as vault-wide values, and specify that a chip tap fills only the three per-provider fields. Keep commit writing only the edited provider's key.
- Revive 'under its old parent if that card is alive' changes today's placement (root at index 0, MainActivity.java:428-433) and does not say where in the card list the subtree goes. Fix: keep index 0 with the subtree intact, or state 'directly after the old parent' and list it as a decision.
- Step 0 ('add the test source set, JUnit 4 and org.json:json') is not trivial in this checkout. There are no Gradle files; app/module.toml already declares [sourceSets.test] but its [dependencies] table has only `implementation`, so test-scoped dependencies have to be added there through CodeAssist, or a Gradle build added alongside. HttpModelSourceTest relies on com.sun.net.httpserver, which is absent on Android's runtime if tests run on-device. The JVM org.json artifact differs from Android's (key order, float formatting). Fix: decide the test runner first; keep the loopback-server test desktop-only; compare parsed structures instead of bytes; add one on-device check that today's fixture files and prefs still load.

## Verdict 2: Locality and defect prevention

**Winner: minimal.**

Locality and defect prevention. For each of the 13 brief defects I asked whether the design makes it impossible through the interface (I), fixes it in one place held by a test (F), or leaves it possible (P), and where each rule lives afterwards. Claims were checked against the source, including AndroidManifest.xml, app/module.toml and res/layout/item_idea_card.xml.

### minimal: 8 / 10

**Strengths.** Verdicts: 1 I, 2 I, 3 F, 4 I, 5 F, 6 F, 7 F, 8 I, 9 I, 10 I, 11 F, 12 F, 13 F. No defect is left open inside the app's own code, and it has no data-loss path. Every gesture and every reply passes through one `send` path, so flight guard, session targeting, save, publish and cue queueing are written once; today each handler calls persistSessions()/refreshAllUi() by hand. Defect 1: the UI never holds a session, the flight records {flightId, sessionId, anchorCardId, selectedIds}, and filter reset, scroll and selection clearing happen only if the target is still active. Defect 2: each indicator is bound to exactly one slot. Defect 4: `IdeaTree.of` snapshots into immutable Rows, the tree is rebuilt once per publish, so there is no cache to go stale, and `IdeaCard.depth` is deleted. Defect 5: the rails mask plus an ItemDecoration to bridge the 10dp row margin (item_idea_card.xml:5), which a view inside the row cannot draw into. Defect 8: Request factories take the tree, so the caller cannot omit lineage or sibling titles; spark also carries existing root titles. Defect 13: one class owns codec, temp+fsync+atomic move, .bak and quarantine, and the active pointer travels in the same atomic write. It reasons correctly that the Deck must be process-scoped, because a ViewModel would let a second Deck open over the same file.

**Weaknesses.** Tree shape has two owners: IdeaTree only derives (`of`, `rows`, `kin`), while insert-after-parent, subtree removal and revive placement live in Deck. `Reply.cards` are IdeaCards stamped by the engine, so the parent exists both as Request.parentId and as the flight's anchorCardId. `State` has no save-health field, so a failed save is silent. Defect 11 is only closed inside the app: `problem()` allows local http, but the manifest has no usesCleartextTraffic and targetSdk is 36, so the platform still refuses it. ProviderProfile carries temperature and globalContext per provider, though they are stored once (AiConfig.java:49-63). The invariant that nothing mutable crosses the seam is false for `State.skills` (CreativeSkill.java:11-18) and `Cue.prompt`; `State.profiles` also hands all five API keys to every Screen. `send` dispatches on an untyped kind with loose arguments. `Filter.OUTLINE` is public, so the UI can send a view that does not exist today. A busy slot drops the tap silently, with no cancel. The parser does not handle an unterminated <think>.

### ports-adapters: 7 / 10

**Strengths.** Verdicts: 1 I, 2 I, 3 I, 4 P, 5 P, 6 F, 7 I, 8 F, 9 I, 10 I, 11 F, 12 F, 13 F at the store. The strongest single mechanisms on the panel. Defect 1: the engine returns CardDraft and never mints an id or parent, so Deck is the one place a card is born and the apply step has no path to the active session. Defect 3: `removeSubtree` returns what it removed and `restore` takes it back; IdeaTree is the only code that changes parentId or list position. Defect 7: the parser is total, handles an unterminated <think>, takes the first balanced value that yields a card, and has a direct table test. Defect 12: one Graveyard-block renderer is shared by the composer and OfflineModelText, and the fallback is reported as a typed Source enum. Defect 13: a Health enum reaches the snapshot, the starter Session is Deck's job so no adapter can overwrite user data, and a fault-injecting in-memory store plus a contract test make SAVE_FAILED testable. `Outcome.BUSY` tells the caller its tap was refused. Settings are modelled as stored: ProviderSettings with selectedId, profiles, temperature and globalContext.

**Weaknesses.** It has the only data-loss path among the four. DeckHolder is a ViewModel whose onCleared lets the in-flight reply finish, apply and save. After back-press and relaunch a second Deck has loaded the same file, and each Deck's whole-file save erases the other's changes. That reopens defect 13 and breaks constraint 7, since the new UI never catches up. Defect 4: `IdeaCard.depth` stays on the class, the tree aliases the session's mutable list and hands out live IdeaCards, and rows are cached until the next edit. There is `setCollapsed` but no star edit, so `toggleStar` leaves cached STARRED rows stale. Defect 5: the 10dp row margin is never addressed, so rails still do not meet, and drawing only the innermost columns puts a depth-6 row at its depth-5 parent's indent. Refusal toasts stay in the Activity and sheets behind Outcome mapping, so that copy is spread out and not JVM-tested. Same manifest cleartext gap as minimal. The EngineRequest factory signatures are elided, and spark carries no existing root titles.

### common-caller: 6.5 / 10

**Strengths.** Verdicts: 1 I, 2 I, 3 F, 4 I, 5 F, 6 F, 7 F, 8 F, 9 I in flight, 10 I, 11 I, 12 F, 13 F. Best treatment of defect 11: it is the only design that noticed the platform is a second cleartext rule and adds usesCleartextTraffic to the manifest so EndpointRule is the single gate, with a test that `ready()` and the engine's refusal agree on every row. Removes `IdeaCard.depth` earliest, at the IdeaTree step. All state-dependent copy sits in one DeckCopy class, so byte-identical strings become one JVM test, and the sheets keep no logic or literals (LabResult arrives formatted). Process-scoped Deck; `detach(screen)` is a no-op for a stale screen; `updatedAt` is stamped on the session that changed rather than the active one (today MainActivity.java:568). Sibling context is frozen when a ticket starts, so a second queued branch sees the first one's children.

**Weaknesses.** The FIFO queue creates new defects. A ticket records kind, ids, skill and labels but not the seed text, and the request is frozen from the session seed when it reaches the head: spark A, then spark B while queued, and both run with B. The provider profile is also bound at the head, so a save while queued changes a request already tapped. The queue is unbounded with no cancel, and each request can take up to 65 s. `optimise` and `ping` take callbacks held by a process-scoped Deck with no cancel, so they fire on dismissed sheets and pin the Activity. Tree edits live in Deck, not IdeaTree, and `rows(filter, armed)` makes the tree know the splice selection. The parser is worded as taking the first balanced JSON value, not the first that yields cards, so a brace in a prose preamble still costs the cards. Rail bridging is assigned to the connector view, which cannot draw into its parent's margin without disabling clipping on two ancestors. DeckStore still builds the starter session itself. DeckState has no seed, so a cold start never fills the dock (today MainActivity.java:156-158). The engine constructor takes only `live`, so the offline source is not actually swappable.

### flexible: 4.5 / 10

**Strengths.** Verdicts: 1 I for cards, 2 F, 3 F, 4 I after step 9, 5 F, 6 F, 7 F, 8 P, 9 I, 10 I, 11 F, 12 F, 13 F. A closed effect set: Landing has no session field, so a Move cannot land cards in another session. Persistent tree operations (`withRoots`, `withChildren`, `without`, `withSubtree`, a Subtree value) keep shape edits in IdeaTree. Rails are complete: indent, pass-through mask, lastSibling, and an ItemDecoration for the row margin. Actions carry their own package-private `run(DeckTxn)`, so there is no dispatch switch to get wrong. `saveProblem` is in the state; the DocumentStore contract test runs against both adapters; ProviderSettings is modelled as stored. Its migration closes defect 1 early with a temporary session-bound reply action.

**Weaknesses.** Open kinds spread every rule this lens cares about. Prompt context is five ContextSources plus per-Move templates joined by string Facts keys, so a typo silently brings back defect 8. `parse` is implemented per Recipe, so the parser rule has five homes. Kinds, lanes, notice kinds and source names are strings; the Prompt Lab sheet compares against "local" and "live". Defect 1 survives as wrong-session view effects: invariant 8 says any landing sets the lens to ALL, and clearSelection and SCROLL_TOP are not conditional on the target being active, so a reply landing in A resets what the user sees in B. Parallel lanes mean the loading bar's text can describe a request other than the one just tapped. A finished lab result stays in `requests` until dismissed: close the sheet before the reply, reopen, and the stale result is rendered and toasted. Lens, Move and ContextSource receive live mutable IdeaCards from every session, so read-only is a convention. `close()` in onCleared cancels in-flight requests, which drops the reply on back-press. Persistence policy is split between the port and Deck's load order. Undo/redo and about 30 public types add state space with no caller. Same manifest cleartext gap.

### Flaws remaining in the winner, with fixes

- Tree shape has two owners: IdeaTree is read-only and Deck edits list position and parentId itself. Fix: add persistent edit operations to IdeaTree and have Deck call only those.
- The engine mints IdeaCards and stamps parentId while the flight separately holds anchorCardId. Fix: the engine returns drafts and Deck stamps everything at apply time.
- A failed save is invisible: `State` has no storage-health field, and DeckFiles has no seam, so the retry rule cannot be tested without making a directory unwritable. Fix: a store port with file and fault-injecting memory adapters, a Health value in `State`, and a contract test.
- Defect 11 is closed only inside the app. `problem()` returns null for http://10.0.2.2 or http://localhost, but AndroidManifest.xml has no usesCleartextTraffic and module.toml sets targetSdk 36, so the platform refuses the request. Fix: set the manifest flag so the rule is the single gate, and test that `problem()` and HttpModelText agree on every host row.
- ProviderProfile holds temperature and globalContext per provider although each is stored once, so `State.profiles` carries five copies and `fill(profileOf(state, id))` can overwrite typed values on a chip tap. Fix: a ProviderSettings value with one temperature and one globalContext, and a draft type.
- The invariant that nothing mutable crosses the seam is false: `State.skills` and `State.skill` are CreativeSkill (public non-final fields), `Cue.prompt` is PromptOptimizationResult (same), and `State.profiles` gives every Screen all five API keys on every render. Fix: immutable row values for skills and the lab result; keep keys out of `State` and deliver the selected profile's key only to the vault sheet.
- `send` switches on an untyped kind with loose arguments, so a mis-wired case compiles. Fix: each Action carries a package-private apply method.
- `IdeaTree.Filter.OUTLINE` is in the public enum, so `Action.filter(OUTLINE)` puts the list in a state the UI cannot reach today. Fix: keep the public Filter to ALL, STARRED and ROOTS and expose the outline as a separate tree method.
- The parser spec omits an unterminated <think>, as when a model is cut off mid-reasoning, so a brace inside it can still be picked up. Fix: strip from an unclosed <think> to the end of the text before scanning.
- The offline heuristic writes the graveyard rules with its own code, a second renderer that can drift from the live prompt's block. Fix: one shared renderer.
- A busy slot drops the tap with no signal, and one card slot serves the whole Deck with no cancel, so a hung request blocks every session for up to 65 s. Fix: abandon the flight on session switch or delete (the late reply already fails the flightId check), or accept a typed result from flight-starting actions so the caller knows the tap was refused.
- The session whose `updatedAt` is stamped when a reply lands in a non-active session is unspecified; today's code stamps the active one (MainActivity.java:568). Fix: stamp the target session.
- `attach(null)` detaches whoever is attached rather than the caller. Fix: identity-checked `detach(screen)`.
- Spark saves the trimmed seed, which raises a SEED cue and rewrites the dock text and cursor; today spark never touches the EditText. Fix: raise SEED only on session change or a Prompt Lab load, not on spark's own save.
- Defects 1 to 3 stay live until migration step 7 of 8. Fix: land an interim session-bound reply and a single busy guard in MainActivity first, then replace them at the cut-over.
